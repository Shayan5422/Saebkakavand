# صائب کاکاوند — Saeb Kakavand

وب‌سایت فارسی موسیقی، با طراحی راست‌به‌چپ و پنل مدیریت مستقل. ساخته‌شده با Next.js، React و TypeScript؛ قابل استقرار مستقیم روی Vercel.

## اجرا روی کامپیوتر

Node.js نسخهٔ ۲۲٫۱۸ یا جدیدتر را نصب کنید. در پوشهٔ پروژه:

```bash
npm ci
npm run setup
npm run dev
```

در مرحلهٔ setup رمز مدیریت را خودتان انتخاب می‌کنید. اگر `.env.local` از قبل وجود داشته باشد، این مرحله آن را تغییر نمی‌دهد. تنظیمات موجود را می‌توانید در همان فایل ویرایش کنید و سرور را دوباره اجرا کنید.

- سایت: `http://localhost:3000`
- مدیریت: `http://localhost:3000/atelier-7k9m`

هیچ لینک ورود مدیریتی در صفحات عمومی وجود ندارد. آدرس پنل به‌تنهایی مجوز ورود نیست؛ تمام عملیات خواندن محتوای مدیریتی، نوشتن و آپلود در سرور به نشست معتبر نیاز دارند.

در حالت محلی، محتوا و عکس‌های تازه در `.data/` ذخیره می‌شوند و با بستن مرورگر از بین نمی‌روند. این پوشه و فایل‌های رمز داخل بستهٔ پروژه و Git قرار نمی‌گیرند. این داده‌های محلی به صورت خودکار به Vercel منتقل نمی‌شوند.

## استقرار روی Vercel

۱. محتویات این پوشه را در یک مخزن Git قرار دهید و آن را در Vercel با نام `saebkakavand` وارد کنید. Framework را **Next.js** بگذارید. دستور Build همان `npm run build` است؛ Output Directory را تغییر ندهید.

۲. از بخش Storage / Marketplace یک پایگاه‌دادهٔ PostgreSQL، مانند Neon یا Supabase، متصل کنید. آدرس اتصال pooled آن را در متغیر `POSTGRES_URL` ذخیره کنید. `DATABASE_URL` نیز پشتیبانی می‌شود.

۳. در ویرایشگر SQL پایگاه‌داده، محتوای `database.sql` را یک بار اجرا کنید. این کار دو جدول می‌سازد و محتوای قبلی را حذف نمی‌کند. روش جایگزین: اتصال دیتابیس را در `.env.local` بگذارید و اجرا کنید:

```bash
npm run db:setup
```

۴. در Vercel یک **Public Blob Store** بسازید و به همین پروژه متصل کنید. متغیر `BLOB_READ_WRITE_TOKEN` باید به محیط پروژه اضافه شود. عکس‌های گالری عمومی هستند؛ رمز و سایر اطلاعات خصوصی نباید در این فضا ذخیره شوند. آپلود مستقیم مرورگر به Blob انجام می‌شود تا محدودیت حجم درخواست توابع مانع بارگذاری عکس نشود.

۵. در Settings → Environment Variables این مقادیر را وارد کنید:

| متغیر | مقدار |
| --- | --- |
| `ADMIN_PASSWORD` | رمز مدیر، حداقل ۱۲ کاراکتر؛ رمز انتخابی خودتان |
| `SESSION_SECRET` | رشتهٔ تصادفی محرمانه، حداقل ۳۲ کاراکتر |
| `POSTGRES_URL` | آدرس اتصال PostgreSQL |
| `BLOB_READ_WRITE_TOKEN` | توکن فضای فایل متصل به پروژه |
| `NEXT_PUBLIC_SITE_URL` | نشانی نهایی سایت، مانند `https://your-domain.com`، بدون `/` پایانی |

برای ساخت SESSION_SECRET می‌توانید از این دستور استفاده کنید:

```bash
node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"
```

مقادیر محرمانه را در Git قرار ندهید. پس از افزودن متغیرها **Redeploy** کنید. سپس نشانی سایت به اضافهٔ `/atelier-7k9m` را باز کنید و با رمز تعیین‌شده وارد شوید.

بدون دیتابیس، بخش عمومی با محتوای اولیه نمایش داده می‌شود؛ ورود و ذخیرهٔ مدیریت در Vercel فعال نمی‌شوند. بدون Blob، آپلود آنلاین فعال نیست. پروژه برای این حالت‌ها خطای قابل‌فهم نشان می‌دهد و ذخیرهٔ موقت روی دیسک Vercel انجام نمی‌دهد.

آزمایش اتصال واقعی PostgreSQL و Blob نیاز به حساب و متغیرهای شما دارد و در نسخهٔ تحویلی انجام نشده است. صفحهٔ عمومی، فرم‌های مدیریت، ذخیرهٔ محلی، انتشار و آپلود محلی آزمایش شده‌اند.

## راهنمای مدیر سایت

۱. نشانی خصوصی پنل را در مرورگر باز کنید و رمز را وارد کنید.
۲. از «آثار و آلبوم‌ها»، یک اثر اضافه کنید یا عنوان، عکس، معرفی و لینک شنیدن آن را تغییر دهید. لینک فایل صوتی اختیاری است؛ فقط فایل دارای مجوز انتشار قرار دهید.
۳. در «گالری تصاویر»، عکس را از کامپیوتر یا موبایل انتخاب کنید، عنوان بنویسید و ذخیره کنید. فرمت‌های JPG، PNG، WebP، GIF و AVIF تا ۸ مگابایت پذیرفته می‌شوند.
۴. در «نوشته‌های مجله»، عنوان، خلاصه، عکس و متن را بنویسید. برای پاراگراف تازه دو بار Enter بزنید.
۵. با گزینهٔ «نمایش در وب‌سایت»، محتوا را منتشر کنید. اگر این گزینه خاموش باشد، محتوا فقط در پنل شما می‌ماند.
۶. از «متن‌ها و ارتباطات»، معرفی، عکس اصلی، ایمیل و لینک اینستاگرام را ویرایش کنید. ایمیل و اینستاگرام اختیاری هستند و تا وقتی وارد نشده‌اند در سایت نشان داده نمی‌شوند.
۷. صبر کنید تا آپلود تمام شود، سپس دکمهٔ ذخیره را بزنید. پیام سبز، ذخیرهٔ موفق را تأیید می‌کند.

با حذف محتوا، رکورد آن حذف می‌شود. فایل‌های آپلودشده به صورت خودکار از Blob پاک نمی‌شوند تا عکس مشترک بین چند نوشته از بین نرود. حذف فایل‌های بدون استفاده را می‌توانید از داشبورد Blob انجام دهید.

برای تغییر رمز، فقط `ADMIN_PASSWORD` را در Vercel عوض و پروژه را مجدداً Deploy کنید. نشست‌های قبلی با تغییر رمز نامعتبر می‌شوند.

## محتوا و تصاویر

- بیوگرافی و فهرست پنج آلبوم و هشت تک‌آهنگ از [صفحهٔ صائب کاکاوند در بیپ‌تونز](https://beeptunes.com/artist/9979685/صائب-کاکاوند) گرفته شده‌اند. این فهرست، محتوای تأییدشدهٔ زمان ساخت است؛ همگام‌سازی خودکار با بیپ‌تونز ندارد.
- سه تصویر آلبوم و سه لینک پیش‌نمایش رسمی از فهرست Apple Music هنرمند آمده‌اند. نسخهٔ کامل آثار به بیپ‌تونز پیوند دارد. برای آثار فاقد جلد قابل‌دریافت، از عکس‌های هنرمند استفاده شده است و مدیر می‌تواند جلد اصلی را جایگزین کند.
- چهار عکس ارسالی شما در صفحهٔ نخست، معرفی و گالری استفاده شده‌اند. برای حفظ چهره، ساز و جزئیات عکس، فایل اصلی حفظ و پس‌زمینه با ماسک CSS در طراحی محو شده است؛ تصویر بدون پس‌زمینهٔ جدید تولید نشده است.
- سه نوشتهٔ مجله متن اولیهٔ تحریریه برای راه‌اندازی سایت هستند؛ به عنوان نوشتهٔ شخصی هنرمند معرفی نشده‌اند. می‌توانید پیش از انتشار عمومی آن‌ها را بازبینی، ویرایش یا پیش‌نویس کنید.
- فونت‌های Amiri و Vazirmatn داخل پروژه قرار دارند؛ سایت برای فونت به سرویس بیرونی وابسته نیست. مجوزهای OFL کنار فایل فونت‌ها موجودند.

## بررسی پروژه

```bash
npm run typecheck
npm test
npm run build
```

آزمایش‌های خودکار، امضای نشست، پایان اعتبار، تغییر رمز، جلوگیری از درخواست از مبدأ دیگر، آدرس‌های نامعتبر، اعتبار فایل عکس و اعتبارسنجی محتوا را بررسی می‌کنند. در بررسی عملی نیز ایجاد پیش‌نویس، انتشار، جلوگیری از بازنویسی نسخهٔ قدیمی، آپلود و بازخوانی عکس و فرم پنل آزمایش شده‌اند. ظاهر دسکتاپ و موبایل، فیلتر آثار، پخش پیش‌نمایش و گالری در مرورگر بررسی شده‌اند.

## ساختار پروژه

- `src/app/` — صفحات عمومی، مجله، صفحهٔ مدیریت و API
- `src/components/` — ظاهر سایت و پنل فارسی
- `src/lib/seed.ts` — متن‌های اولیه و عکس‌ها
- `src/lib/releases.json` — فهرست اولیهٔ آثار
- `src/lib/store.ts` — ذخیرهٔ محلی و PostgreSQL با کنترل نسخهٔ محتوا
- `src/lib/security.ts` — نشست امضاشده و بررسی درخواست‌ها
- `public/images/` — تصاویر آمادهٔ سایت
- `database.sql` — جدول‌های موردنیاز استقرار
- `.env.example` — نام متغیرهای محیطی، بدون رمز

در محیط آنلاین، داده‌ها در PostgreSQL و عکس‌های تازه در Blob ذخیره می‌شوند و با Deploy مجدد از بین نمی‌روند.
